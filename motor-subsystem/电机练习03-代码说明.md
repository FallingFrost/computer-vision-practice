## 0. 一句话总结

现在按下按钮，机器人会跑**一整条死区扫描**：从左轮**完全静止**开始，PWM 从 0 一档档加到 60（步长 5），
每一档重复 5 遍，每遍都是「先停稳 → 再通电 1 秒 → 每 50ms 记一个样本」。

输出的是**一行一个样本**的 CSV，列是 `wheel, direction, PWM, trial_num, sample_num, speed_cps, ...`——
**和练习 2 的格式不一样**，别混用（§4 讲清楚为什么）。

按下按钮后**约 2 分 10 秒**自动跑完并停转。**跑的中途再按一次按钮可以中止**。

## 3. 代码讲解

### 3.1 常量表（`Controller.h`）

| 常量 | 值 | 含义 |
|---|---|---|
| `DEADBAND_WHEEL` | 0 | 0 = 左轮，1 = 右轮 |
| `DEADBAND_DIRECTION` | +1 | +1 = 正转，−1 = 反转 |
| `DEADBAND_PWM_MIN` | **0.0** | 扫描起点。见下方"为什么从 0 开始" |
| `DEADBAND_PWM_MAX` | 60.0 | 扫描终点 |
| `DEADBAND_PWM_STEP` | 5.0 | 步长 → **13 档** |
| `DEADBAND_REPEATS` | 5 | 每条 ladder 走 5 遍 → **共 65 轮** |
| `DEADBAND_SAMPLE_CALLS` | 5 | 每 5 次 `update()` 采一次 → **50ms / 20Hz** |
| `DEADBAND_SAMPLES_PER_TRIAL` | 20 | `N_s` → `T_run` = 20 × 50ms = **1.0 秒** |
| `DEADBAND_REST_MIN_CALLS` | 100 | 静止期下限 1.0 秒 |
| `DEADBAND_REST_QUIET_CALLS` | 50 | 且要求最后 **0.5 秒计数完全不变** |
| `DEADBAND_REST_MAX_CALLS` | 300 | 上限 3.0 秒，到点仍未停稳就**标记未收敛** |

> **为什么从 0 开始扫**：PWM = 0 那一档不是浪费，它是**噪声地板**。
> 零指令下测到的位移，就是桌面震动、线缆牵拉、编码器抖动这些干扰的总和。
> 后面每一档判"到底动没动"，都拿这个实测值当基准——**阈值是量出来的，不是猜的**。
> 代价只是多一档（约 2 秒）。

### 3.2 时间线

每轮（trial）严格照课程的 Algorithm 1：

```
停转 ──► 等 T_rest ──► 记初始计数 ──► 加 PWM ──► 每 Δt 采一个样本，共 N_s 个
 |         ≥1.0s          (line 6)     (line 7)      (line 9-11)
 |         且需实测停稳
 └─ Algorithm 1 line 4: Set motor PWM to 0
```

| 项 | 值 |
|---|---|
| 静止期 | ≥ 1.0 秒，且最后 0.5 秒计数不变才放行（上限 3.0 秒） |
| 运行期 | 20 个样本 × 50ms = **1.0 秒** |
| 单轮合计 | 约 **2.0–2.1 秒** |
| 总轮数 | 13 档 × 5 遍 = **65 轮** |
| **总时长** | **约 2 分 10 秒** |

### 3.3 `testDeadband()` 状态机

```cpp
// ① 整条 ladder 走完了：显式停两个电机，再放信号
if (db_complete) {
  robot.setMotorPWM(0, 0);
  setSignal(0);          // ← 只有这里和下面的中止分支能调
  return;
}

// ② 通电运行中按按钮 = 中止
bool past_first_trial = (db_rep > 0) || (db_pwm_index > 0);
if (db_in_run && past_first_trial && robot.isButtonPressed()) {
  robot.setMotorPWM(0, 0);
  setSignal(0);
  return;
}

// ③ 静止段：一直等，直到确认停稳
if (!db_in_run) {
  if (deadbandStepRest(robot)) {      // 返回 true = 停稳了
    db_last_count = deadbandWheelCount(robot);   // line 6 记初始计数
    db_last_ms    = now;
    db_sample     = 0;
    db_in_run     = true;
    deadbandApplyCommand(robot);                 // line 7 加 PWM
  }
  return;
}

// ④ 运行段：按 Δt 采满 N_s 个样本
deadbandStepRun(robot, now);
```

**六个刻意的设计决定，都要能讲出来：**

1. **③ 静止期为什么不是"等固定 2 秒"**：课程的原文要求是 *"Verify: check that the value you have given to T_rest is long enough for the robot to come to a complete stop."*
   写死一个时长只是**假设**停住了，不是**验证**。这里改成：至少等 1.0 秒，**且**要求最后 0.5 秒里编码器计数一个都没变——
   等效于「半秒内位移 < 0.28mm」，也就是速度低于 **0.56 mm/s**。这才是能写进报告的证据，
   而且通常比写死 2 秒**更快**（轮子一般 0.3 秒就滑停了）。

   > 顺带：静止期的 `rest_residual_counts` 记的是**从发停止指令那一刻起算**的总位移，所以它**包含滑行段**。
   > 这是故意的——它正好是"断电后轮子还能滑多远"的直接测量。

2. **"计数没变"必须配合"读取成功"才算证据**：`update()` 里 `robot.getEncoders()` 失败时**缓存原样不动**，
   于是在数据里和"轮子完全静止"长得一模一样。一次 I2C 打嗝就能伪造出一个完美的静止证据。
   所以 `update()` 现在把返回值存进 `last_encoder_read_ok`，静止判定要求它同时为真。
   这是练习 2 留下的一个静默故障，练习 3 正好踩在它上面，所以必须先修。

3. **扫描中途绝不能调 `setSignal(0)`**：`setSignal(0)` 会调 `reset()`，而 `reset()` 会把扫描索引清零。
   练习 2 里 `measureWheelSpeed` 每轮结束调它是**对的**（练习 2 的"一轮"就是"整次运行"），
   但死区扫描的"一轮"只是 65 轮里的一轮——照抄会让机器人**永远在第一档循环**。
   所以这里只有两条路径能调它：整条 ladder 跑完、或者被中止。

4. **重复放在最外层**：课程的伪代码是"每档跑完所有重复再进下一档"。我把它**反过来**了——
   外层是"走遍每一档"，内层才是下一档。理由：
   - 如果每档连着跑 5 遍，任何**随会话漂移**的因素（电池压降、橡胶升温、线缆越缠越紧）
     都会沿着 PWM 轴累积，伪装成"高档位响应变差"这个**根本不存在**的结论。
     重复放外层，漂移对每一档的影响**相同**，只会表现为「第 1 遍和第 5 遍不一样」。
   - 顺带一个好处：**中途中止不浪费数据**。跑完 3 遍就停，13 个档位各有 3 轮可比数据；
     而按伪代码的顺序，跑一半只覆盖到前几档。

   > 每一遍**内部**仍然严格是「升序 + 固定步长」，所以这不是违背 Algorithm 1，是把重复索引提到外层。
   > 课程导言其实**专门提醒过这件事**：*"it will be important to think about whether using iteration may also impact the observed motor performance."*

5. **`trial_num` 是"第几遍"，不是"第几轮"**：所以它在同一次扫描里是 1→5，每个 PWM 值都会出现
   `trial_num` = 1,2,3,4,5 各一次。这正是课程示例输出的语义（示例里 PWM 25 有 `trial` 1 和 2）。
   ⚠️ 与练习 2 的 `trial_num`（跨轮累加、永不重置）**语义不同**，所以用的是独立的 `db_rep`，没有复用那个变量。

6. **`direction` 和 `wheel` 两列是从实际发出去的指令推导的**，不是一个独立配置项。
   配置和实际不一致时，数据不会**报错**，只会**安静地标错**——这类错误事后极难发现。

### 3.4 为什么要留 `rest_settled` 和 `rest_residual_counts` 两列

课程第 6 步原文：*"Keep any continued-motion test separate from the starts-from-rest dataset."*

这句话有个**阴险的推论**：如果某一轮的 `T_rest` 其实不够、轮子还在慢慢滑，那一轮就**已经变成了 continued-motion 数据**，
但它会安安静静地混在 starts-from-rest 数据集里，没人看得出来。

所以这两列不是锦上添花，**它们就是"把两类数据分开"的证据**：

- `rest_settled = 1` → 这一轮是干净的从静止起步，可以用
- `rest_settled = 0` → 这一轮没停稳（撞到了 3 秒上限），**分析时整轮剔掉**

| 追加列 | 用途 |
|---|---|

## 5. 物理测试步骤

> 机器人**倒扣在桌上、轮子悬空**（本次选定的条件 = **空载**）。
> 绝不用手按住通电的轮子（打齿）。绝不能让它有机会摔下桌子——**摔弯电机轴是永久损坏**。

1. 插 USB-C，在 Arduino IDE 里**上传**（⚠️ 上传前必须先停掉串口抓取，串口是独占的）
2. 开抓取脚本（见 §6），**先起脚本、再按按钮**

- PWM 30 那一档是不是**时转时不转**？（之前的实验里它是双稳态，这次要看它复现不复现）

### 扫描长这样

```

left,forward,0,1,1,0.000,0.000,50.1,38120,1234,0,0,1
```

### 三个你能自己算出来的数

**① 量化台阶 = 5.6116 mm/s**

50ms 采样间隔下，**1 个计数** = `1 ÷ 0.05 = 20 counts/s`，换算成 mm/s：
`20 × 0.280578` = **5.6116 mm/s**。

也就是说：**低于 5.6 mm/s 的运动，读数就是 0**；速度读数实际上是 5.6116 的整数倍跳变。
（对比 10ms 采样的台阶是 **28 mm/s**——这就是为什么这里坚持用 50ms，见 §8 第 3 条。）

**② 每档每样本应该有多少个计数**

用之前测到的稳态速度反推（`mm/s ÷ 0.280578 = counts/s`，再 × 0.05）：

| PWM | 之前的实测速度 | counts/s | 每 50ms 的计数 |
|---|---|---|---|
| 0 | 0 | 0 | **0**（噪声地板） |
| 30（转起来时） | 88 mm/s | ~314 | ~**15.7** |
| 40 | 129.4 mm/s | ~461 | ~**23.1** |
| 60 | 210.2 mm/s | ~749 | ~**37.4** |

**③ 噪声地板应该非常小**

PWM = 0 那 5 轮，`encoder_count` 应该**基本纹丝不动**（理想情况整轮 0 个计数）。
如果那一档就有几十个计数，说明桌面在震、或者线缆在拉——那么后面判"动没动"的阈值就得相应放宽。

### 故障对照表

| 你看到的 | 最可能的原因 |
|---|---|
| **串口完全没输出** | ① 串口被 Arduino IDE 的 Serial Monitor 占着 ② 板子没在跑新代码 ③ USB-C 线只供电不传数据 ④ `CDCOnBoot` 被改成了 `cdc`（见 §6） |
| 抓取窗口里**满屏 `[丢弃]`** | 表头形状和脚本预期的不一致，来问我 |
| 数据行**不到 1300 行** | 抓取起晚了（板子已经在跑）；或者中途 Ctrl+C 早了 |
| **第一列是 `wheel` 不是数字** | 正常，这就是练习 3 的格式 |
| 扫描**只跑一档就停** | 中止逻辑被误触发了。你是不是按按钮时**摁住没放**？ |
| 扫描**停在第一档一直循环** | 不该发生（`setSignal(0)` 只在收尾/中止调用），来问我 |
| `rest_settled` **出现 0** | 那一轮 `T_rest` 不够，轮子没停稳。把 `DEADBAND_REST_MAX_CALLS` 调大重跑 |
| `rest_residual_counts` **普遍几十上百** | 正常——那是停止后的**滑行**距离，不是错误 |
| **PWM 0 那档就有可观位移** | 桌面震动或线缆牵拉。先把线理顺，再看要不要放宽阈值 |
| `dt_ms` **经常大于 55** | I2C 挤了。第一个该关的是 `update()` 里的 `robot.getPose()`（死区例程根本不用它），来问我 |
| 计数**偶尔不连续跳** | I2C 读偶发失败，缓存留旧值。偶发可容忍，频繁就是硬件/线缆问题 |
| 同一个 PWM **有的轮转、有的轮不转** | **这不是故障**，这就是双稳态，正是这个练习要量的东西 |

### 持续运动的判定规则（提案，**你要自己认可并能在报告里辩护**）

课程要求 *"a defensible rule for separating a twitch from sustained movement"*。规则本身**没有唯一正确答案**，
但必须说清楚。下面这套是我建议的起点。

先从每轮 trial 里算这几个量（`c_i` = 第 i 个样本的累计计数，`t_i` = 它的时间戳）：

| 量 | 定义 | 物理含义 |
|---|---|---|
| `C_total` | 整轮位移（计数） | 走了多远 |
| `v_late` | **后半段**（后 10 个样本）的平均速度 | 稳态速度，避开启动瞬态 |
| `n_late_moving` | 后半段里 \|Δc\| ≥ 1 的样本数 | 运动的**持续性** |
| `v_tail` | 最后几个样本的速度 | **结束时还在动吗** |

然后**四分类**，而不是简单的动/不动：

| 类别 | 判据 | 物理含义 |
|---|---|---|
| **STALL** | `\|C_total\| ≤ θ_null` | 完全没动 |
| **TWITCH** | 有位移，但**后半段完全静止** | 挣脱静摩擦后卡死 |
| **CREEP** | 后半段还在缓慢累积，但 `\|v_late\| < θ_speed` | 低速爬行 |
| **SUSTAINED** | `\|v_late\| ≥ θ_speed` 且后半段大部分样本在动 | **持续运动** |

两个阈值的定法，这才是"可辩护"的关键：

- **`θ_null` 用 PWM = 0 那一档实测**：取那 5 轮里 \|C_total\| 的最大值 + 2 个计数。
  **噪声地板是量出来的，不是猜的**——这就是扫描从 0 开始的原因。
- **`θ_speed` 要报敏感性，不要只报一个数**：建议取 **50 counts/s（≈14 mm/s）**，
  然后在 **20–200 counts/s** 区间里扫一遍，**证明结论不变**。
  如果怎么取都是同一个答案，那才叫"可辩护"。

最后，死区这样报告：

> `p_sustained(PWM)` = 该档判为 SUSTAINED 的轮数 ÷ 5。
> 死区上界 = 最大的 `p_sustained = 0` 的档；阈值下界 = 最小的 `p_sustained = 1` 的档。
> **报告成区间**，中间的档位用 `p_sustained` 如实写出来（比如"PWM 30 是 3/5"），不要强行给一个单点。

**三条必须知道的统计限制**（写进报告会显得很扎实）：

1. **5 轮不够支撑"一定动"**。5/5 全成功，单侧 95% 置信下界只有 **0.55**——你只能说"成功率 ≥ 55%"，不能说"必定"。
   10 轮是 0.74，20 轮是 0.86。所以**粗测用 5 轮够，精测过渡区那几档要加到 10–20 轮**。
2. **"非零样本数"这个判据本身不可辩护**——它依赖采样间隔。同一个 20 mm/s 的爬行，
   50ms 采样几乎每个样本都非零，10ms 采样约一半是零。这是把 `v_late` / `v_tail` 单独拎出来的原因。
3. **旧的 `pwm30.csv` / `pwm40.csv` 可以当交叉验证**：那几轮"起转成功"的速度 88.1 / 87.3 / 87.3 mm/s，
   和用 PWM 40、60 两点线性外推到 PWM 30 的 **89.9** 吻合得惊人。
   这正好证明**失败的轮次不是"转得慢"，而是"根本没起转"**——是静摩擦高于动摩擦，不是电池。

## 附录：为什么这个练习重要

死区是**数字孪生最容易漏掉、后果最直接**的一个非线性：

- 在**真机**上，控制器发一个很小的非零指令，轮子**根本不动**——表现为低速时一顿一顿、或者完全推不动。
- 在**仿真**里，如果假定死区不存在，那么任何按比例响应设计的控制器，
  从仿真搬到真机都会在低速段失效。

所以练习 3 量出来的不是一个数字，是**"多小的指令等于没发"**这条界线。
练习 4（饱和）量的是另一头"多大的指令等于全发"，两个合起来才是电机真正可用的输入范围。

而这次测量最容易被做废的三个地方：

1. **轮子没真停就开始测** → 测成了 continued-motion，混进 starts-from-rest 数据集
2. **按伪代码顺序扫** → 会话漂移伪装成 PWM 效应
3. **判定规则没定就说"死区是 35"** → 报告里站不住
