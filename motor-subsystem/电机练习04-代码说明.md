## 0. 一句话总结

现在按下按钮，机器人会跑**一整条饱和扫描**：PWM 从 60 一档档加到 200（步长 10），每档重复 5 遍。
每一遍的节奏是 **冷却 1.0 秒 → 加指令后稳定 0.6 秒 → 测量 1.0 秒**。

输出的是**一行一个测量样本**的 CSV，速度列叫 **`settled_speed_cps`**（注意不是练习 3 的 `speed_cps`）。

按下按钮后**约 3 分 15 秒**自动跑完并停转。**测量期间再按一次按钮可以中止**。

> ⚠️ **这是本课程里唯一会持续跑在 200 满幅值的练习。** 课程反复警告长时间高 PWM 会**永久烧毁电机**。
> 上手前先读 §5 的"先做飞行员测试"。

## 3. 代码讲解

### 3.1 常量表（`Controller.h`）

| 常量 | 值 | 含义 |
|---|---|---|
| `SATURATION_WHEEL` | 0 | 0 = 左轮，1 = 右轮（单轮模式用） |
| `SATURATION_DIRECTION` | +1 | +1 = 正转，−1 = 反转 |
| `SATURATION_OPPOSITE_PAIR` | **false** | true = 双轮反向自转（见 §3.4） |
| `SATURATION_PWM_MIN` | 60.0 | 起点。**和练习 3 重叠一档**，用来做跨练习交叉验证 |
| `SATURATION_PWM_MAX` | 200.0 | 终点 = 课程支持的幅值上限 |
| `SATURATION_PWM_STEP` | 10.0 | 步长 → **15 档** |
| `SATURATION_PWM_LIMIT` | 200.0 | 发送前 `constrain` 用。常量写错了也不会超限 |
| `SATURATION_REPEATS` | 5 | 走 5 遍 → **75 轮** |
| `SATURATION_COOL_CALLS` | 100 | 冷却 1.0 秒，**电机恒为 0** |
| `SATURATION_SETTLE_CALLS` | 60 | 稳定 0.6 秒，**不报告任何数据** |
| `SATURATION_SAMPLE_CALLS` | 5 | 每 5 次 `update()` 采一次 → 50ms |
| `SATURATION_SAMPLES_PER_TRIAL` | 20 | 每轮 20 个样本 → 测量 1.0 秒 |

### 3.2 时间线与总账

每一遍（trial）三个相位：

```
SAT_COOL ──────────► SAT_SETTLE ────────► SAT_MEASURE ──────► 下一轮
1.0s, 电机=0          0.6s, 指令已加        1.0s, 指令保持
不打印                速度还在变            每 50ms 打印一行
                      ⚠️ 一个字都不打印     ← 只有这里的数进得了均值
```

| 项 | 值 |
|---|---|
| 单轮 | 2.6 秒（1.0 + 0.6 + 1.0） |
| 总轮数 | 15 档 × 5 遍 = **75 轮** |
| **总时长** | **约 3 分 15 秒** |
| 通电占比 | 1.6 / 2.6 = **61.5%** |
| 单次连续通电 | **最长 1.6 秒**（稳定+测量），不会更长 |
| 数据行数 | 75 × 20 = **1500 行**（+1 表头） |
| 每个 PWM 值 | 5 轮 × 20 样本 = **100 行** |

> **61.5% 的通电占比听着高，但发热风险比看上去低。** 电机的电流由
> `(供电电压 − 反电动势) / 电阻` 决定：**轮子悬空自由旋转时反电动势接近供电电压，电流反而最小**。
> 真正烫的是**堵转**（轮子被卡住）——那才是电流最大、且转子不转没有风冷的情况。
> 我们全程轮子悬空，所以是低电流工况。**但这条推理的前提是轮子转得起来**，
> 所以 §5 要求你先做飞行员测试、并用手背碰一下电机外壳确认温度。

### 3.3 为什么这里也用 50ms，而不是课程举例的 10Hz

课程原文举的例子是 *"sampling at 10Hz (10 times a second), 3 seconds of operation would collect 30 samples"*。
那是**举例**，不是规定。我选 50ms / 20Hz，理由有三：

1. **和前两个练习用同一条采样链**。符号方向、差分方式、单位换算全部一致，跨练习对比才成立。
2. **高转速下量化根本不是问题**。PWM 60 时每 50ms 已有约 37 个计数；到 200 会更多。
   练习 2 之所以纠结采样率，是因为低速时**计数太少**——这个问题在这一段不存在。
3. **采样越密，"稳定期够不够"越看得清**。20 个点比 10 个点更容易看出开头几个样本有没有偏低。

> 反过来，如果你把测量窗口缩短到 0.5 秒，就只有 10 个样本——均值还行，但**看不见窗口内的漂移**。

### 3.4 `SATURATION_OPPOSITE_PAIR`：什么时候打开

| | 单轮（默认） | 双轮反向 |
|---|---|---|
| 电机指令 | 只给一个轮子，另一个 0 | 左 +PWM、右 −PWM |
| 反作用力矩 | 不抵消，机身想转 | 两个互相抵消，机身稳 |
| 每采样点行数 | 1 行 | 2 行（左右各一行） |
| 与练习 3 可比性 | **完全一致** | 构型不同 |
| 适用场景 | **轮子悬空**（我们现在的做法） | 压在桌面上自转时必须用 |

我们默认**关**。理由是练习 3 的死区是单轮悬空测的，饱和用同一构型，两者才能拼成一条完整的「输入 → 输出」曲线。
课程推荐双轮反向，针对的是**机器人压在桌面上做高速测试**——那种情况下单轮会让机器人跑掉。
如果你之后要测带载饱和，把它改成 `true` 即可，代码已经写好了。

### 3.5 三个刻意的设计决定，都要能讲出来

1. **相位严格分离，稳定期绝不进均值。**
   课程 AI 路线专门点名：*"check that a settling interval is not accidentally included in the settled-speed average."*
   代码里的做法是：`SAT_SETTLE` 是**独立的相位**，它在整个 0.6 秒内**一个字节都不打印**；
   切换到 `SAT_MEASURE` 时才记下基准计数，而且**第一个样本要再等一个完整采样间隔**。
   所以稳定期的瞬态在结构上**不可能**混进均值——不是靠"我算了一下够长"，是靠代码里没有这条路径。

2. **重复放在最外层**（和练习 3 同一个理由）。
   如果每档连着跑 5 遍，**会话漂移**（电池压降、绕组升温、橡胶变软）会沿 PWM 轴累积，
   伪装成"高档位响应变差"这个**根本不存在**的结论——而这恰好是练习 4 要回答的问题，
   所以这里的漂移污染**比练习 3 更致命**（练习 4 看的就是曲线在哪变平）。
   重复放外层，漂移对每一档影响相同，只会表现为「第 1 遍和第 5 遍不一样」。

3. **`constrain` 放在发送之前。** `SATURATION_PWM_MAX` 是 200，正好是课程支持的幅值上限。
   万一常量被改错，`constrain(magnitude, 0, SATURATION_PWM_LIMIT)` 保证发出去的永远在范围内。

### ⚠️ 和练习 3 只差**一个列名**，但差一个字母就报错

| | 练习 3 | 练习 4 |
|---|---|---|
| 速度列名 | `speed_cps` | **`settled_speed_cps`** |
| 其余 5 个必需列 | `wheel, direction, PWM, trial_num, sample_num` | **完全相同** |

notebook 源码里写明了：

> *Expected CSV columns: `wheel`, `direction`, `PWM`, `trial_num`, `sample_num`, and `settled_speed_cps`.*

**前 6 列是硬要求**，名字必须逐字一致（`PWM` 大写）。后 5 列是我加的，notebook 不读：

| 追加列 | 用途 |
|---|---|
| `speed_mm_s` | 换成人看得懂的单位（× 0.280578） |
| `dt_ms` | **实测**采样间隔 |
| `time_ms` | 该样本的 `millis()`——**这个练习特别有用**，能把「会话时间」当协变量排查升温/压降漂移 |
| `encoder_count` | 本行的累计计数，可据此自行复算 |
| `other_encoder_count` | 另一个（未驱动）轮的计数，作为"底盘有没有被扰动"的正交证据 |

- `PWM` 与 `settled_speed_cps` **都带符号**；前进为正，沿用练习 2 的符号约定
- `trial_num` 是**第几遍**（1–5），每个 PWM 值各出现一次——和练习 3 同一套语义
- 表头沿用 `csv_header_done` 的做法，整个上电周期**只打一次**

## 5. 物理测试步骤

> 机器人**倒扣在桌上、轮子悬空**（和练习 3 同一条件 = **空载**）。
> ⚠️ **高速档位下轮子转得很快，手指、线缆、纸片全部让开。** 碰一下就可能打齿。

### 先做"飞行员测试"（课程明确要求）

课程原文：*"Run a cautious pilot... Check the sequence, acquisition intervals and stop before collecting repeated measurements."*

改两个常量 → 重新上传 → 跑一次：

| 常量 | 飞行员值 | 目的 |
|---|---|---|
| `SATURATION_REPEATS` | **1** | 只跑一遍，约 40 秒 |
| `SATURATION_PWM_MAX` | **100** | 先只到 100，不上 200 |

这次要确认的：表头对不对、行数对不对、**每个相位时长对不对**、按钮能中止、**跑完用手背碰一下电机外壳烫不烫**。
确认无误后改回 5 / 200，重新上传，再跑完整轮。

### 完整轮

1. 插 USB-C，在 Arduino IDE 里**上传**（⚠️ 上传前必须先停掉串口抓取）
2. 开抓取脚本（见 §6），**先起脚本、再按按钮**
3. **按一下 StampC3 的按钮开始**，手松开
4. 约 3 分 15 秒后自动跑完停转
5. **中途想停就再按一次按钮**（按一下松手）

**要观察的**：
- 高档位（180–200）轮子有没有明显的**音调变化**？——转速上不去时声音会不再变尖，这是饱和的**听觉**线索
- 电机外壳温度（跑完手背碰一下，**别用手指按**）
- 冷却那 1 秒里轮子是不是明显减速——那是真的断电了，不是"以为断了"

## 5.5 预期效果：先知道该看到什么

### 硬预期（这些是确定的，对不上就是有问题）

| 项 | 值 |
|---|---|
| 第一行 | 表头，11 列 |
| 数据行数 | **正好 1500 行**（+1 行表头 = 1501） |
| 每个 PWM 值 | **100 行**（5 轮 × 20 样本） |
| 档位 | **15 档**：60,70,…,200 |
| `trial_num` | 1–5，每个 PWM 值各出现一次 |
| 行间隔 | 50ms（`dt_ms` 列） |
| 总时长 | **约 3 分 15 秒**，然后自动停 |

### 关键参考线：**"如果不饱和"应该是多少**

练习 3 测到 40–60 段是高度线性的，斜率约 **14.2 counts/s 每 PWM**，PWM 60 处是 **752 counts/s**。
把这条直线延长上去，就是"**响应完全不饱和**"的参考值：

| PWM | 线性外推 (counts/s) | 换算 mm/s |
|---|---|---|
| 60 | 752 | 211 |
| 80 | 1036 | 291 |
| 100 | 1320 | 370 |
| 120 | 1604 | 450 |
| 140 | 1888 | 530 |
| 160 | 2172 | 609 |
| 180 | 2456 | 689 |
| **200** | **2740** | **769** |

**这张表就是你的判读基准**：
- 实测**贴着这条线** → 没有饱和，响应在测试范围内仍是线性的
- 实测**系统性低于这条线且越来越低** → 那就是饱和，看它在哪一档开始明显掉队
- 实测**高于**这条线 → 说明 40–60 段的斜率外推不成立（也可能，比如低速段本来就不是线性的），要回头查

> 课程原话：*"The fastest output response of the motor is not by itself evidence of saturation."*
> 所以**不要**看到 200 档速度最高就宣布饱和——**饱和的证据是"相邻档位的速度增量变小"**，
> 这正是 notebook §6 要算的 `diff()`。

### 另一个必查项：稳定期到底够不够

**做法**：在 Colab 里把某一档的 20 个样本按 `sample_num` 画出来（横轴采样序号，纵轴速度）。

- 曲线**一开始就平** → 稳定期够长，数据可用 ✅
- **开头几个样本明显偏低、然后爬升到平台** → 稳定期太短，`SATURATION_SETTLE_CALLS` 要调大重跑 ❌

这就是 AI 路线警告的那个坑的**事后可检验形式**。因为每个样本都留了，这个检查不需要额外实验。

### 故障对照表

| 你看到的 | 最可能的原因 |
|---|---|
| **串口完全没输出** | ① 串口被 Serial Monitor 占着 ② 板子没跑新代码 ③ 线只供电不传数据 ④ `CDCOnBoot` 被改成了 `cdc` |
| 抓取窗口**满屏 `[丢弃]`** | 表头形状和 `-ExpectedHeader` 不一致，来问我 |
| 数据行数**不是 1500** | 抓取起晚/停早；或飞行员测试时改了 `SATURATION_REPEATS` 忘了改回来 |
| 某个 PWM 只有 **20 行** | 那一遍只跑了 1 轮 —— 实际是 `trial_num` 只出现了 1 次，说明 `SATURATION_REPEATS` 还是 1 |
| **第一列是 `left`/`right` 不是数字** | 正常，练习 3/4 都是这个格式 |
| 列名是 `speed_cps` 不是 `settled_speed_cps` | **板子上跑的还是练习 3 的固件**，没上传成功 |
| 扫描**跑一半就停** | 中止逻辑被触发。你是不是按按钮时**摁住没放**？ |
| `dt_ms` **经常 > 55** | I2C 挤了。第一个该关的是 `update()` 里的 `robot.getPose()`（本练习不用它），来问我 |
| **所有档位速度都一样** | 指令没真发出去，或轮子被卡住（堵转）。**立刻停机检查** |
| 高档位**速度反而下降** | ① 电池压降（`time_ms` 列能看出来）② 绕组升温（看 `trial_num`，第 5 遍是否系统性低于第 1 遍）③ 线缆越缠越紧 |
| 电机**明显发烫 / 有异味** | **立刻按按钮中止，拔电，让电机冷却。** 这是烧毁前兆 |

### 7.5 怎么报告结论

notebook §6 会给出 `response_summary`，其中 `speed_change_cps` 就是**相邻档位的速度增量**。

**判据**：*"A sustained reduction towards zero slope is evidence for saturation."*
关键词是 **sustained**（持续）和 **repeatable**（可重复）——**单点变小不算**，
课程要求 *"a repeatable flattening across several PWM command levels"*，即**连续多档**都掉下来。

**报告成区间**，课程原文要求：

> *"note down where you believe the point of saturation is reliably reached. Write this value down as an interval, for example 240 ≤ x ≤ 250, or x ∈ (240, 250)."*

**三种都可以写，但要说清是哪一种**：

| 情况 | 怎么写 |
|---|---|
| 明显看到多档连续变平 | 给出拐点区间，如 `x ∈ (150, 170]`，附上该区间内各档的增量和重复离散度 |
| 没看到平台 | **"在安全测试的 60–200 范围内未分辨出饱和"**，课程明确接受这个结论 |
| 只看到"最后一个点没怎么涨" | 写成**未解决的边界**，并说明"再加哪几档、重复几轮能把边界收窄" |

> 课程原话：*"It is acceptable to conclude that no plateau was resolved in the range you tested."*
> 而且 *"An unresolved boundary is useful when you can explain the measurement that would narrow it."*
> ——**不要为了交差硬凑一个拐点。**

**竞争性解释要交代**（AI 路线第 5 条要求"挑战一个竞争解释"）：
速度上不去可能是 ① 电机反电动势到顶（真饱和）② 电池带不动（压降）③ 驱动器效率变化 ④ 线缆缠紧增加阻力。
廉价的区分手段：
- 把指标对 **`time_ms`** 画 → 如果随会话时间单调下降，那是 ② 电池
- 把指标对 **`trial_num`** 画 → 如果第 1 遍和第 5 遍系统性不同，那是 ②/③ 的漂移
- **把 60 档重新跑一次放在最后** → 如果 60 档也掉了，说明整段会话有漂移，不全是饱和

## 附录：为什么这个练习重要

练习 3 和练习 4 量的是**同一条曲线的两端**：

```
速度
  ↑
  │                      ← 练习 4：这里还涨吗？（饱和）
  │              ______
  │            /
  │          /            ← 这一段近似线性（练习 5 测它的斜率 = 增益）
  │        /
  │______/
  │
  └──┬──────────────────→ PWM
     ↑
   练习 3：这里能动吗？（死区）
```

两个端点合起来才是**电机真正可用的输入范围**。课程原文点出的后果：

> *"If a controller asks an already saturated motor for more output speed, the motor has no further capability in reality and cannot increase.
> For a two-wheel differential steer robot, if one wheel is not able to respond as expected, the total motion of the robot is likely to behave unexpectedly."*

也就是说：**饱和是差速转向机器人跑偏的一个直接机制**——一个轮子已经到顶，另一个还没，控制器却以为两边都听它的。

而在数字孪生里，漏掉饱和意味着仿真中的机器人**能做出真机做不到的动作**，
Phase 2 里所有基于仿真的控制器参数都会失效。

这个练习最容易做废的三个地方：

1. **稳定期的数混进了均值** → 测到的不是稳态速度，是"加速过程中的某个值"
2. **按档位顺序连续跑** → 升温/压降伪装成饱和
3. **看到速度最高的点就说是饱和点** → 课程明确说这不构成证据
