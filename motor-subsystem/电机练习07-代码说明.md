## 3. 代码讲解

### 3.1 试验表（在 `Controller.cpp` 里，不在头文件）

```cpp
const StepTrial_c STEP_TRIALS[] = {
  {"rise_1", "fit",       STEP_PWM_LOW,  STEP_PWM_HIGH},   // 60 → 140
  ... 共 5 条 ...
  {"fall_1", "held back", STEP_PWM_HIGH, STEP_PWM_LOW },   // 140 → 60
  ... 共 5 条 ...
};
```

**为什么放在 .cpp 而不是头文件**：轮数、留出划分、两条指令是这个**表**的属性。
如果把它们拆成头文件里的独立常量，改了常量而没改表，头文件就在说谎。
现在**表是唯一事实来源**。

**为什么下降阶跃是好的留出测试**：课程原话 *"A falling step or a new step size can provide
a useful held-back test."* 下降是一次**真正没见过的转换**，不是同一条曲线再放一遍。
而且课程明确提示：*"The same limit need not describe rising and falling responses"*
—— 所以如果上升段拟合出的 τ 预测不了下降段，那本身就是有价值的发现。

### 3.2 为什么只发 10 列（这不是偷懒）

10ms 采样意味着**每秒 100 行**。课程专门警告：

> *"Keep command generation separate from telemetry reporting so that printing or transmitting
> a record cannot alter the intended step timing."*

实测算过带宽：

| | |
|---|---|
| 行宽 | 58 字符 + CRLF = **60 字节** |
| 产出速率 | 100 行/秒 → **6000 B/s** |
| 串口容量 | 115200 8N1 → 11520 B/s |
| **占用率** | **52%** |
| 缓冲区净排空 | **+55 字节 / tick** |

净排空为正，说明 256 字节的发送缓冲**不会积压**，`Serial.print` 不会阻塞到影响时序。

但再加列就危险了：多一个 `speed_cps`（+9 字节）会把占用推到 **70%**，净排空只剩 45 字节/tick。
**在唯一一个时序敏感的练习里拿余量换便利不划算**，所以**只保留 notebook 要的 10 列**。
速度由 notebook 从 counts + timestamps 差分得出——课程就是这么设计的。

### 3.3 时间线

每轮四个相位：

```
STEP_GAP ──────► STEP_INITIAL_HOLD ──► STEP_TRANSIENT ──► STEP_FINAL_HOLD
1.0s              1.0s                  1.4s                1.0s
电机=0            施加 u0                施加 u1（只改一次）   保持 u1
不记录            每 10ms 记一行         每 10ms 记一行       每 10ms 记一行
                  phase=initial_hold    phase=transient     phase=final_hold
```

| 项 | 值 |
|---|---|
| 单轮 | 4.4 秒（1.0 + 1.0 + 1.4 + 1.0） |
| 轮数 | **10**（5 上升 + 5 下降） |
| **总时长** | **约 44 秒** |
| 每轮记录行数 | (1.0+1.4+1.0)/0.01 = **340 行**（间隙不记录） |
| **总行数** | **3400 行** |
| 文件大小 | 约 **199 KB** |

### 3.4 三个刻意的设计决定

1. **间隙不记录。** `STEP_GAP` 期间电机是 0，但轮子还在从上一轮减速。
   这时候记的行如果标成 `initial_hold`，那是在描述一件没发生过的事。
   所以整个间隙一列都不打。

2. **快照写在相位切换判断之前。** 伪代码里也是这个顺序
   （先 `store(...)` 再判断 `if phase = INITIAL_HOLD and ...`）。
   结果是**边界那一行带的是旧指令**——因为计数是在改指令之前读的。
   下一行才是新指令。这样每条计数都带着它被读取时真正生效的指令。

3. **指令重试而不是每周期重发。** `setMotorPWM` 返回是否被 I2C 确认。
   发失败就一直重试，成功就不再发。每周期重发同样能保证送达，但会让 I2C 流量翻倍——
   而这个循环恰恰是全项目里余量最小的地方。

### 3.5 ⚠️ `step_timestamp_ms` 的语义与它的限制

`step_timestamp_ms` 在**初始保持开始时**就算好了（= 当前时刻 + 1.0 秒），
之后每一行都带这个值。

**为什么不能等真正切换时再写**：阶跃前的那些行**不可能知道一个还没发生的时间**。
流式输出没有未来信息。所以用**计划时刻**，全程一致。

**代价**：真正的指令变化发生在**第一个 `now >= step_timestamp_ms` 的周期**，
也就是最多晚 **1 个 tick（≤10ms）**。

这个限制要写进报告——课程序列里明确要求区分
*"acquisition, speed calculation, and reporting"* 与电机物理：
**10ms 的阶跃时刻不确定度是测量管线的属性，不是电机的**。

### 3.6 ⚠️ 10ms 采样的量化代价（必须知道）

轮子直径 32mm、358.3 counts/rev → 1 计数 = 0.280578 mm。

| 采样间隔 | 1 个计数的速度当量 |
|---|---|
| 50 ms（练习 2–6） | 20 counts/s = **5.6 mm/s** |
| **10 ms（练习 7）** | 100 counts/s = **28.1 mm/s** |

所以 10ms 下速度读数是 **100 counts/s 的台阶**。60→140 的阶跃里速度变化约
**1123 counts/s**（749 → 1872），只跨 **约 11 个量化台阶**。

**这意味着曲线是阶梯状的，不是光滑的。** 报告里要如实说。

**补救办法（分析阶段可选）**：不连续差分，改成隔 2–3 个样本差分——
量化降到 33–50 counts/s，代价是时间分辨率变成 20–30ms。
notebook 默认是**连续差分**；要不要平滑、平滑多少，是你要交代的取舍。

### **τ ≈ 131 ms**（用练习 3 数据预估的）

练习 3 的每一轮其实就是一次"0 → PWM"的阶跃，只是 50ms 采样。
用它拟合指数，15 轮的结果：

| | |
|---|---|
| τ 中位数 | **130.7 ms** |
| τ 范围 | 111.6 – 147.6 ms |
| 一致性 | 好（±13%） |

**对练习 7 的含义**：10ms 采样下瞬态约跨 **52 个样本**（4τ）。
50ms 采样只有约 10.5 个点——**这就是换到 10ms 的全部理由**。

### 三个候选模型应该长什么样

| 模型 | 形状 | 判据 |
|---|---|---|
| **瞬时（instantaneous）** | 在 t₀ 直接跳到新速度 | 作为参照，预期不成立 |
| **斜率限制（slew-rate）** | 一段**斜率恒定**的直线斜坡，然后平 | 若成立，斜坡段的 dω/dt 应≈常数 |
| **一阶滞后（first-order lag）** | 起始最快，越接近目标越慢 | 若成立，63.2% 处对应 t = τ |

**预期看到一阶滞后**：τ ≈ 131ms 是个明确的有限值，而且一阶滞后的形状是
"开头最陡、然后变缓"——这和练习 3 里观察到的启动瞬态一致。

**但课程明确接受其它结果**：
> *"A clear slew limit, a clear first-order lag, a combination, or **no resolvable delay at the
> available sampling rate** are all legitimate evidence-led outcomes."*

### S 和 τ 的来历

课程要求 *"adjust S and τ using only trials labelled `fit`"*。
用 5 轮上升段拟合的结果：

| | notebook 默认 | **实测拟合** | 差 |
|---|---|---|---|
| **S（斜率上限）** | 1500 cps² | **4636 cps²** | **3.1 倍** |
| **τ（时间常数）** | 0.18 s | **0.1332 s** | **35%** |

> τ 实测 **0.1332 s**，逐轮 0.1311–0.1365（很一致）。
> 而练习 3 数据**事前预估**的是 **0.1307 s**——差 **2%**。两条独立路径互证。

### 这个偏差会把结论整个翻过来

MAE（counts/s，越小人越好）：

| 用哪组参数 | 轮次 | instantaneous | slew_rate | **lag** | 最好 |
|---|---|---|---|---|---|
| 示例默认值 | fit | 105.6 | 140.0 | **73.1** | **lag** |
| 示例默认值 | held back | 173.4 | 190.4 | **155.1** | **lag** |
| **实测拟合值** | fit | 105.6 | **62.0** | 67.4 | **slew** |
| **实测拟合值** | held back | 173.4 | **140.3** | 147.9 | **slew** |

**用示例默认值时，斜率限制模型看起来最差（比"瞬时"还差）；用自己的参数时它变成最好。**
原因很直白：S = 1500 只有实测值的 1/3，斜坡被拉得太慢；τ = 0.18 又比实测大 35%，
两条曲线都偏了，而偏的方向恰好对 lag 有利。

**当前 Colab 那一轮得到的"lag 最好"是参数没调的结果，不是机器人的性质。**

### ✅ 结论：斜率限制模型胜出，而且留出检验支持它

**slew 在拟合轮和留出轮上都最好**（57.7 vs 63.8；141.5 vs 148.7）。

这一点比"拟合误差更小"强得多——课程特意强调过：

> *"A falling or differently sized step is a stronger test than another sample from the fitting trace."*
> *"Freeze every fitted coefficient before using the reserved observations."*

**排序在没参与拟合的下降段上保持不变**，说明这不是过拟合。
`instantaneous` 在两边都差一倍左右 → **"指令一变速度就跳过去"被明确否定**。

### 但同时要写的三条保留意见

1. **slew 和 lag 的差距只有 5–10%**，别写成"确定是斜率限制"。
2. **量化地板**：10ms 下速度被舍入到最近的 100 counts/s，完美模型的 MAE 也只能到 ~25。
   现在最好的 141.5（held-back）/ 57.7（fit）分别是地板的 **5.7 倍 / 2.3 倍**
   → **两个简单模型都还有没解释掉的结构**。课程允许再加组合模型：
   *"Treat a combined slew-and-lag model as an additional candidate to use only if the simpler
   models leave clear evidence unexplained."*
3. **上下行不对称**（下表）说明**同一组参数不该同时用于上升和下降**。

而 §17 打出的方程确认参数确实生效了：

```
Slew candidate: omega_hat(t) = 700.000 +1 * min(4636.000 * t, 1200.000)
Lag candidate: omega_hat(t) = 700.000 +1200.000 * (1 - exp(-t / 0.133))
```

### 两个必须写进报告的判断

**① 动态是真实可分辨的，不是"测不出来"。**
`instantaneous` 的 MAE 是 105.6（fit）/ 173.4（held back），
比两个动态模型差一倍左右。所以"指令一变速度就跳过去"这个假设被数据**明确否定**了。

**② 但 slew 和 lag 的差距很小，别过度宣称。**
62.0 vs 67.4（fit）、140.3 vs 147.9（held back）——**只差 5–8%**，而且排序在留出集上保持
（这是它比"只看拟合误差"强的地方）。

同时要注意一个**量化地板**：10ms 采样下速度被舍入到最近的 100 counts/s，
舍入误差 ±50 均匀分布，所以**再完美的模型也只能做到 MAE ≈ 25 counts/s**。
现在最好的模型是 62，**约为地板的 2.5 倍**——说明**两个简单模型都还有没解释掉的结构**。

课程对此有明确指示：

> *"A combined model may begin with pronounced curvature and take longer to settle."*
> *"Treat a combined slew-and-lag model as an additional candidate to use only if the simpler
> models leave clear evidence unexplained."*

2.5 倍于地板就是"clear evidence unexplained"的信号。**组合模型（先斜率限制、后一阶趋近）
是下一步该试的候选**，而不是在 slew 和 lag 之间硬挑一个。

**③ 上升和下降不对称。**

| | 上升（fit） | 下降（held back） | 差 |
|---|---|---|---|
| S | 4636 cps² | **4072 cps²** | −12% |
| τ | 0.1332 s | **0.1157 s** | **−13%** |

下降段逐轮 τ：0.1187 / 0.1158 / 0.1157 / 0.1148 / 0.1139（很一致），
和上升段的 0.1311–0.1365 **完全不重叠**。

课程原话：*"The same limit need not describe rising and falling responses, both wheels, or both
directions."* —— **这不是实验做坏了，这就是结论**：减速比加速快约 13%。

> 这也正是留出检验该做的事：用上升段冻结的参数去预测下降段，
> 失败得**系统而且一致**，说明是物理差异而非噪声。

## 附录：为什么这个练习重要

前六个练习合起来描述的是**稳态**：给定指令，轮子最终转多快。那是一条**折线图**。
但真实机器人**从来不在稳态上跑**——它总是在变速。

```
速度
  ↑
ω∞┤              ┌────────────────   ← 前六个练习量的是这条水平线的高度
  │          ╱
  │       ╱                            ← 练习 7 量的是这段斜坡
  │    ╱                                 直线？指数？还是瞬间跳过去？
ω0┤───╯
  └──────────────────────────→ 时间
     ↑
    指令在这一刻变了
```

课程点出的后果很具体：

> *"A digital twin that jumps immediately to the new settled speed may therefore predict the
> final motion correctly while predicting the path, stopping distance, or controller timing poorly."*

也就是：**仿真里机器人"想停就停"，真机上它要滑一段**。差的那一段就是这里的 τ。

**为什么判别模型形状比拟合一个数更重要**：
- 如果是**斜率限制**，那么多大的阶跃都无所谓——斜坡斜率是常数，大到一定程度就会"顶到上限"
- 如果是**一阶滞后**，那么阶跃越大，起始斜率越大，到达时间只由 τ 决定

这两种模型给出**不同形状的曲线**，控制器设计要用的参数也就不同。
用一个"上升时间"数字糊过去，就没法区分它们。

**这个练习最容易做废的三个地方**：

1. **采样太慢** → 瞬态只剩几个点，三种形状看起来一样（课程原话：*"At a slow sampling or
   reporting rate these shapes can look deceptively similar"*）
2. **打印拖累时序** → 阶跃时刻被上报本身推后，测出来的是"上报延迟"不是电机动态
3. **拿留出检验的失败当实验失败** → 上下不对称本身就是结论
